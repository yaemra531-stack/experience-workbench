# 个人经验工作台

## 文章库

文章以 Markdown 存放在 `articles/`，`articles/index.json` 按序号记录标题、简介、话题、封面、文件名和导入日期。正文只读，不占用浏览器的工作台数据或备份。第 1 篇的列表链接为社媒版，文末可进入保留参考资料的原版。今后导入新文章时，以标题检查重复：已存在的跳过并告知，再将新 Markdown 放入目录、更新索引并发布。

个人工作台由经验工作台、创作工作台和战略看板组成。经验工作台用于记录经验；创作工作台分为短线、长线、分析。分析用于拆解内容，写下一句话升级点；关联短线后自动标记为已用。战略看板显示执行原则、时间块、栏目和最近一条待用升级点。

## 每天怎么用

1. 30 分钟保底：录一条想法观察并发布。
2. 1～1.5 小时做第二条：新东西上手、盘点或痛点解法。
3. 1～1.5 小时分析加升级：拆一个好内容，选一个升级点并做一条。
4. 晚上 1 小时写文章，作为当天复盘。

被打断时从后往前砍，保底永远不砍；手里常备两条存货。详细规则见 [短线战略执行手册](docs/短线战略-执行手册.md)。

## 保存、备份和恢复

数据保存在当前浏览器的 localStorage，不自动同步到 GitHub、其他浏览器或设备。经验工作台在「设置与备份」下载、恢复 JSON；创作工作台的数据保存在 `creation-workbench-v1`，在左侧「备份创作数据」「导入创作备份」分别备份和恢复。创作备份包含短线、长线和分析，旧版不含分析的备份仍可导入。创作导入按记录 ID 只新增、不覆盖；经验和创作需分别备份。战略看板内容在代码中，显示状态保存在浏览器本地；看板读取创作记录生成统计。

保管 JSON 备份；清理浏览器数据或更换浏览器可能丢失本地记录。选择性 Markdown 导出用于分享，不代替 JSON 备份。GitHub 上的网站代码不包含个人浏览器里的记录。

## 每周同步作品

每周一次，让 Codex 通过 Computer Use 查看抖音作品，从实际作品提取信息，生成创作工作台备份格式的 JSON，再在创作工作台「导入创作备份」。导入只新增、不覆盖：同一作品的 ID 需跨次稳定一致，才能重复导入不重复计数；缺失信息留空，不编造。发布状态和栏目应以实际可核验的信息为准。

## 修改战略与冻结规则

战略文字在 `strategy.js` 顶部的 `STRATEGY` 中，故意不提供网页编辑，避免日常使用时频繁改动战略。第 100 条之前只修 bug，不增加功能。

## 本地运行

在此目录运行 `python3 -m http.server 8000`，访问 `http://127.0.0.1:8000/`。本地和线上浏览器数据独立；如需查看已有记录，应通过相应的 JSON 备份恢复。首次打开需要加载内置 Pyodide 组件。
